# Plan 01-02: Domain Data Model & Four Seed Cases

## Goal
Implement the core relational domain model (`Resource`, `PhysicalItem`, `DigitalItem`, `Borrowing`, `User`) according to `docs/database/schema-spec.md` and `docs/lld/sprint-1-lld.md`, provide the 4 fixed seed cases via database initialization scripts, and verify derived availability calculation logic through backend tests.

## Proposed Tasks

### Task 1: Domain Entities & Enums
- **Objective**: Create JPA entity classes and enums.
- **Files**:
  - `backend/src/main/java/com/librio/domain/PhysicalItemStatus.java` (`AVAILABLE`, `BORROWED`, `OVERDUE`)
  - `backend/src/main/java/com/librio/domain/Resource.java`
  - `backend/src/main/java/com/librio/domain/PhysicalItem.java`
  - `backend/src/main/java/com/librio/domain/DigitalItem.java`
  - `backend/src/main/java/com/librio/domain/Borrowing.java`
  - `backend/src/main/java/com/librio/domain/User.java`
- **Details**:
  - Map entity relationships: `1 Resource -> 0..N PhysicalItem`, `1 Resource -> 0..1 DigitalItem`, `1 PhysicalItem -> 0..N Borrowing`, `1 User -> 0..N Borrowing`.

### Task 2: Database Schema & Four-Case Seed Script
- **Objective**: Provide SQL schema definition and seed data for local database startup.
- **Files**:
  - `backend/src/main/resources/schema.sql`
  - `backend/src/main/resources/data.sql`
- **Details**:
  - Seed Case 1 (Physical Available): `ID=1`, Title="Clean Code", Authors="Robert C. Martin", 5 physical copies (2 `AVAILABLE`, 3 `BORROWED`), 1 digital item.
  - Seed Case 2 (Physical Out of Stock): `ID=2`, Title="Refactoring", Authors="Martin Fowler", 3 physical copies (0 `AVAILABLE`, 3 `BORROWED`), no digital item.
  - Seed Case 3 (Digital Only): `ID=3`, Title="Designing Data-Intensive Applications", Authors="Martin Kleppmann", 0 physical copies, 1 digital item.
  - Seed Case 4 (Mixed): `ID=4`, Title="Structure and Interpretation of Computer Programs", Authors="Harold Abelson, Gerald Jay Sussman", 2 physical copies (1 `AVAILABLE`, 1 `BORROWED`), 1 digital item.

### Task 3: Availability Derivation & Repositories
- **Objective**: Implement Spring Data JPA Repositories and service logic to derive physical and digital availability counts dynamically.
- **Files**:
  - `backend/src/main/java/com/librio/repository/ResourceRepository.java`
  - `backend/src/main/java/com/librio/repository/PhysicalItemRepository.java`
  - `backend/src/main/java/com/librio/repository/DigitalItemRepository.java`
  - `backend/src/main/java/com/librio/service/ResourceService.java`
- **Details**:
  - Implement query helper methods to count total physical copies, count available copies (`status = 'AVAILABLE'`), and check digital item existence.
  - Do NOT persist availability in a separate DB table (enforce BC-03).

### Task 4: Backend Integration & Seed Verification Tests
- **Objective**: Write automated integration tests for repository and service layer verifying seed data and availability aggregation.
- **Files**:
  - `backend/src/test/java/com/librio/repository/ResourceRepositoryTest.java`
  - `backend/src/test/java/com/librio/service/ResourceServiceTest.java`
- **Details**:
  - Test Case 1: ID=1 returns `totalCopies=5`, `availableCopies=2`, `digitalAvailable=true`.
  - Test Case 2: ID=2 returns `totalCopies=3`, `availableCopies=0`, `digitalAvailable=false`.
  - Test Case 3: ID=3 returns `totalCopies=0`, `availableCopies=0`, `digitalAvailable=true`.
  - Test Case 4: ID=4 returns `totalCopies=2`, `availableCopies=1`, `digitalAvailable=true`.

## Verification
- Run `mvn clean test` (or `./gradlew test`) in `backend/` and confirm all 4 seed test cases pass cleanly.
