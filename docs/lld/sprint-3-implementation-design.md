# Librio — Sprint 3 Implementation Design

**Scope:** Overdue presentation, physical return, protected digital access and librarian resource administration.

This document is the implementation baseline for the Sprint 3 frontend snapshot. It intentionally records only the decisions required to build and verify the vertical slices; detailed controller and repository mechanics remain in source code.

## 1. Overdue and Return

- A borrowing is active when `returned_at IS NULL`.
- `overdue` is derived by the backend as `returned_at IS NULL AND due_at < server time`; it is not persisted as a borrowing status.
- Reader and librarian borrowing DTOs expose the server-derived `overdue` boolean.
- `POST /librarian/borrowings/{borrowingId}/return` locks the borrowing and exact physical item, sets `returned_at`, and moves the item from `BORROWED` to `AVAILABLE` in one transaction.
- A repeated or competing return receives `409 BORROWING_ALREADY_RETURNED`. Missing records receive `404 BORROWING_NOT_FOUND`; inconsistent item state receives `409 BORROWING_ITEM_CONFLICT`.

## 2. Protected Digital Access

- A `digital_item` row marks that a resource has protected digital content.
- `GET /resources/{resourceId}/digital-access` requires `ROLE_READER` and returns a capability containing a backend content URL.
- `GET /resources/{resourceId}/digital-content` also requires `ROLE_READER` and returns a PDF response.
- Sprint 3 uses a server-generated demo PDF so the access-control vertical slice can be verified without selecting an object-storage provider. Persistent file storage, signed URLs and DRM remain deferred.

## 3. Librarian Resource Administration

- `ROLE_LIBRARIAN` can create, read and update managed resources.
- `resource.category` is optional and limited to 100 characters.
- Authors remain persisted as a comma-separated string but are represented as a JSON array at the API boundary.
- Resource and item identifiers are generated by the server.
- Creating/updating `physical.totalCopies` reconciles exact item rows:
  - increasing the count creates `AVAILABLE` items;
  - decreasing the count deletes only `AVAILABLE` items;
  - reduction fails with `409 RESOURCE_IN_USE` if insufficient available items can be removed.
- Removing physical access is equivalent to setting the desired copy count to zero and follows the same safety rule.
- Digital access creates/removes the one-to-one `digital_item` marker. Content storage remains outside this sprint.

## 4. API Summary

| Method | Path | Role | Purpose |
|---|---|---|---|
| `GET` | `/librarian/borrowings?status=active` | Librarian | List active borrowings with derived overdue flag |
| `POST` | `/librarian/borrowings/{id}/return` | Librarian | Atomically return the exact borrowed item |
| `GET` | `/resources/{id}/digital-access` | Reader | Obtain protected digital capability |
| `GET` | `/resources/{id}/digital-content` | Reader | Open protected demo PDF |
| `GET` | `/librarian/resources/{id}` | Librarian | Load resource administration form |
| `POST` | `/librarian/resources` | Librarian | Create resource and access records |
| `PUT` | `/librarian/resources/{id}` | Librarian | Update metadata and reconcile access records |

## 5. Compatibility Boundaries

- Sprint 1 public discovery endpoints remain public.
- Sprint 2 request, checkout, cancellation and My Library contracts remain compatible; borrowing responses gain only the additive `overdue` field.
- Custom rejection reason is not part of this Sprint 3 baseline.
- Development mocks may assist isolated UI work but must be disabled for integration/E2E and production builds.
